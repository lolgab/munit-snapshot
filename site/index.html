Snapshot tests for Scala

snaptest records what your tests produce as generated Scala files, and fails with a diff and a link to the line when it changes.

Set up snaptest munit, ScalaTest, ZIO and four more

The entry snaptest writes

            

          

          

            Plain strings, triple quotes, or a margin for values over many
            lines: snaptest picks the literal a reviewer reads fastest.

From test to snapshot

          

            
Write a test that returns a value.

            

              Mix the snaptest trait of your framework into the suite, then
              call assertSnapshot or define a
              snapshotTest.
            

          

          

            
Run it once, then commit the file.

            

              snaptest writes snapshots/ExampleTestSnapshots.scala
              next to the test. It compiles with your tests, so build tools
              rerun them when it changes.
            

          

          

            
Change the code, and it fails.

            

              The failure shows the diff and links to the snapshot's line.
              Rerun with SNAPTEST=always when the change is
              intended.
            

          

        

        

          

            

              
ExampleTest.scalamunit

              
import snaptest.*

class ExampleTest extends munit.FunSuite, MunitSnapshots:
  snapshotTest("one plus one") {
    1 + 1
  }

  test("parser") {
    assertSnapshot(parse("1 + 2"))
  }

            

            

              
snapshots/ExampleTestSnapshots.scala2 recorded

              
// Generated by snaptest, update with SNAPTEST=always
// format: off
// $COVERAGE-OFF$
package example

/** Snapshots of [[ExampleTest]] */
object ExampleTestSnapshots extends snaptest.Snapshots {
  def entries = Seq(
    "one plus one" -> "2",
    "parser" -> "Sum(Num(1), Num(2))",
  )
}

Why snaptest

          

            Snapshots compile with your tests, failures link to the line, and
            CI never records them silently.
          

          

            

              No build plugin and no configuration: add the dependency for
              your framework and run your tests. Cached builds rerun them when
              a snapshot changes.
